### Glossário C/C++

* **`volatile`**: Significa que o valor dessa variável pode mudar sem que isso esteja diretamente escrito no código. Isso impede que o compilador otimize ou faça uso errado de uma variável (como substituí-la por um valor fixo em cache). É especialmente fundamental para variáveis que guardam valores lidos em um registrador (no hardware) ou em rotinas de interrupção (ISRs).
* **`__attribute__((aligned(4)))`**: Diretiva para o compilador pôr uma estrutura em um endereço de memória que seja múltiplo de 4. Isso facilita e acelera a leitura do processador (já que arquiteturas de 32 bits buscam dados em blocos de 4 bytes) e ajuda a diminuir o risco de fragmentação ou desalinhamento de memória.
* **`static`**: Funções ou variáveis com esse atributo só podem ser usadas dentro do arquivo (translation unit) onde foram declaradas, ou seja, não podem ser chamadas de outros arquivos (não devem aparecer nos headers visíveis a outros). Variáveis estáticas locais também são inicializadas apenas uma vez e mantêm seu valor entre chamadas subsequentes da função.
* **`inline`**: Sugere ao compilador que insira o corpo da função diretamente no local onde ela é chamada, em vez de realizar um salto de execução (chamada de função tradicional). Isso elimina o *overhead* (tempo de empilhar e desempilhar registradores), melhorando a velocidade em trechos críticos de execução, mas pode aumentar o tamanho do binário final.
* **`static inline`**: Combina a restrição de escopo e a otimização de chamada. A função é expandida no local de chamada e sua visibilidade fica restrita ao arquivo atual. É a forma padrão e mais segura de definir pequenas funções diretamente em arquivos de cabeçalho (`.h`), pois evita o erro de "múltiplas definições" (multiple definition) caso o header seja incluído por vários arquivos `.c` diferentes.
* **`extern "C"`**: Instrui o compilador C++ a não alterar os nomes das funções durante a compilação (processo conhecido como *name mangling*). Isso permite que um código C++ consiga chamar funções escritas em C (e vice-versa), garantindo que o ligador (*linker*) consiga encontrar a referência correta dos símbolos matemáticos e lógicos na hora de montar o executável final.
* **`typedef`**: Cria um apelido (alias) para um tipo de dado já existente. Serve para tornar o código mais legível e fácil de manter. Permite criar nomes padronizados e explícitos para o tamanho dos dados (como `typedef unsigned int uint32_t;`) e simplifica a declaração de tipos complexos, como `structs`, `enums` e ponteiros de função.
* **`#pragma message`**: Diretiva de pré-processador que imprime uma mensagem de texto informativo no console durante o momento da compilação. É útil para deixar lembretes para outros desenvolvedores ou sinalizar o status de um trecho de código (ex: `#pragma message "Lembrar de otimizar este loop na versão 2.0"`).
* **`#warning`**: Diretiva de pré-processador que gera um aviso (*warning*) durante a compilação, mas não interrompe o processo de build. É muito utilizada para alertar que determinado recurso está obsoleto (*deprecated*) ou que uma configuração secundária pode causar comportamento indesejado.
* **`#error`**: Diretiva de pré-processador que interrompe imediatamente a compilação e exibe uma mensagem de erro fatal. É crucial para impedir que o código seja compilado se macros obrigatórias não estiverem definidas, ou se houver incompatibilidade de arquitetura e versões (ex: `#error "Este código suporta apenas processadores de 32 bits"`).
* **`#pragma once`**: Diretiva não-padrão (porém suportada por quase todos os compiladores modernos) colocada no topo de arquivos de cabeçalho (`.h`). Garante que o arquivo seja incluído apenas uma única vez durante a compilação de um código-fonte. Substitui a necessidade de escrever as tradicionais guardas de inclusão com macros (`#ifndef HEADER_H ... #define HEADER_H ... #endif`), deixando o código mais limpo e rápido para o pré-processador analisar.
